# Шумомер

Уеб приложение за измерване на шум в реално време. Бекендът (Python, FastAPI) записва
от микрофона, смята нивата и спектъра и ги праща през WebSocket към браузъра.
Интерфейсът е чист HTML с Tailwind CSS (през CDN) и JavaScript – без build стъпка.
Измерванията се пазят в SQLite база (един файл, `noise.db`).

## Възможности

Приложението е разделено на шест раздела. На компютър те са в странична лента, на
телефон – в долна лента. Всеки раздел има свой адрес (`/#analysis`, `/#records/5`…),
така че може да се отвори директно или да се сложи в отметки.

**Ниво** (`#meter`)
- циферблат 0–140 dB с цветни зони, плавна стрелка и отметка за максимума;
- избор на честотно претегляне (A / C / Z) и времево (Fast 125 ms / Slow 1 s);
- **„Прилича на“** и **жива скала на шума** – 15 познати звука от шепот до реактивен
  двигател; маркерът се движи по скалата и осветява най-близкия;
- минимум, средно (Leq), максимум, L10 / L50 / L90, пик и пикова честота за сесията;
- графика на последната минута с подсказка при посочване;
- **цял екран** (удобно на телефон хоризонтално) и **снимка** – PNG с нивото,
  сравнението и графика на последната минута.

**Анализ** (`#analysis`)
- спектър 20 Hz – 20 kHz със задържане на максимума;
- форма на вълната;
- третинооктавни ленти (31 ленти по IEC 61260) като графика или таблица;
- спектрограма за последните ~30 секунди.

**Доза** (`#dose`)
- дозиметър по NIOSH и OSHA: доза в %, TWA, прогноза за 8 часа и колко още е
  безопасно при текущото ниво;
- таблица с допустимото време при различни нива, с отбелязан текущия ред.

**Записи** (`#records`)
- запис в базата: всяка секунда се пазят LAeq, LAFmax, LAFmin, LCeq, LZeq и LZpeak;
- отчет: LAeq, LAFmax/min, LCeq, LZeq, LZpeak, L10 / L50 / L90, време над
  60/70/80/85/90 dB, хистограма, графика във времето със събитията от алармата,
  шумова доза, на какво прилича средното ниво и кога е бил най-шумният момент;
- проверка за нискочестотен шум (LCeq − LAeq);
- бележки, CSV експорт, печат, преименуване, изтриване.

**Аларма** (`#alarm`)
- праг и минимална продължителност, банер, звуков сигнал и известие в браузъра;
- всяко превишаване се пази като събитие.

**Настройки** (`#settings`)
- избор на микрофон;
- калибриране: офсет на ръка, типичният офсет, или по еталонен шумомер.

Клавиши: интервал – старт/стоп, 1–6 – раздел, F – цял екран, R – нулиране, S – снимка.

## Инсталиране

Нужен е Python 3.10 или по-нов.

```bash
python -m venv .venv
```

Windows (PowerShell):

```bash
.venv\Scripts\Activate.ps1
```

Linux / macOS:

```bash
source .venv/bin/activate
```

После:

```bash
pip install -r requirements.txt
```

На Linux може да е нужна и системната библиотека PortAudio (`sudo apt install libportaudio2`).

## Стартиране

С истински микрофон:

```bash
python backend/main.py
```

В демо режим (симулиран сигнал, не трябва микрофон):

```bash
python backend/main.py --demo
```

Отвори <http://localhost:8000>. Сървърът слуша на `0.0.0.0:8000`, така че от телефон в
същата мрежа може да се отвори `http://<IP-на-компютъра>:8000` (на Windows разреши
Python в защитната стена при първото стартиране).

> Звукът винаги се записва от микрофона на компютъра, на който върви сървърът.
> Телефонът само показва данните. Известията в браузъра работят само на `localhost`
> (или през https) – на телефона остават банерът и звукът.

Опции:

| Флаг           | По подразбиране | Описание                         |
|----------------|-----------------|----------------------------------|
| `--demo`       | изключен        | симулиран сигнал вместо микрофон |
| `--port`       | `8000`          | порт                             |
| `--host`       | `0.0.0.0`       | адрес, на който да слуша         |
| `--db`         | `noise.db`      | път до файла на базата           |

## Калибриране

Звуковата карта дава само числа спрямо максимума, който може да запише (dBFS) – там
0 е най-силното, а всичко останало е отрицателно. За да станат dB SPL (това, което
показват шумомерите), към тях се добавя калибрационен офсет. По подразбиране той е
**120 dB** – типичната стойност за MEMS микрофоните в телефони и лаптопи (−26 dBFS при
94 dB SPL). Така работят и приложенията като Decibel X: те имат готов офсет за всеки
модел телефон.

За по-точни стойности:

1. Сложи еталонен шумомер (или калибратор 94 dB) до микрофона и пусни постоянен шум.
2. В „Калибриране по еталон“ въведи какво показва той и натисни „Калибрирай“ – офсетът
   се изчислява от последните 3 секунди.

Офсетът може да се въведе и на ръка, а бутонът „Типичен“ връща 120 dB. Офсетът,
устройството и настройките на алармата се пазят в `config.json`. Всеки запис помни
офсета, с който е направен. Точността зависи от микрофона – вградените в лаптопи
микрофони често имат автоматично усилване, което изкривява резултата. Ако е възможно,
изключи го от звуковите настройки на системата.

В демо режим нивото бавно се мени между ~40 и ~80 dB, а от време на време има „удари“
до ~100 dB – с праг 85 dB алармата се задейства сама.

## Как се смята

- **A- и C-претегляне** – цифрови филтри от аналоговите криви по IEC 61672 чрез билинейна
  трансформация. Под 4 kHz съвпадат с кривите; над 10 kHz отклонението е в толерансите за клас 1.
- **Fast / Slow** – експоненциално усредняване на квадрата на сигнала с τ = 125 ms / 1 s.
- **LAeq (1 s)** – енергийно средно за всяка секунда; LAeq на целия запис е енергийно средно
  на тях. L10 / L50 / L90 се смятат от едносекундните стойности.
- **Третинооктавни ленти** – от FFT с 8192 точки; мощността в лентата се интегрира между
  границите ѝ, затова и тесните ниски ленти дават правилна енергия.
- **Шумова доза** – при ниво L допустимото време е 8 ч / 2^((L − критерий) / обменен
  коефициент): NIOSH 85 dB / 3 dB, OSHA 90 dB / 5 dB, нива под 80 dB не се броят.
  На живо се смята по LAS, в записите – по едносекундните LAeq.

Това е полезен инструмент за ориентировъчни измервания, но не замества сертифициран шумомер.

## Структура

```
backend/
  main.py    – FastAPI: страници, API, WebSocket, аларма, записи
  audio.py   – запис / демо сигнал, филтри, нива, спектри
  db.py      – SQLite: записи, измервания, събития, отчети
static/
  index.html   – обвивката и шестте раздела
  common.js    – цветове, форматиране, помощни функции за графиките
  state.js     – общото състояние (последен кадър, офсет, претегляне)
  meter.js     – „Ниво“ и „Доза“: циферблат, скала, статистика, доза, снимка
  analysis.js  – „Анализ“: спектър, вълна, третинооктавни ленти, спектрограма
  records.js   – „Записи“: запис, списък и отчет
  app.js       – навигация, връзка със сървъра, аларма, настройки, клавиши
```

## API

| Път                          | Метод  | Описание                                                  |
|------------------------------|--------|-----------------------------------------------------------|
| `/ws`                        | WS     | съобщения `data` (~20/s), `status`, `alarm`               |
| `/api/status`                | GET    | състояние: запис, устройство, офсет, аларма               |
| `/api/devices`               | GET    | входни устройства                                         |
| `/api/device`                | POST   | `{"index": 3}` или `{"index": null}` за системното        |
| `/api/calibration`           | POST   | `{"offset": 92.5}`                                        |
| `/api/start`, `/api/stop`    | POST   | старт / стоп на измерването                               |
| `/api/alarm`                 | POST   | `{"enabled": true, "threshold": 85, "duration": 3}`       |
| `/api/events?limit=20`       | GET    | последни събития от алармата                              |
| `/api/recording/start`       | POST   | `{"name": "Спалня, нощ"}` – започва запис в базата        |
| `/api/recording/stop`        | POST   | спира записа                                              |
| `/api/sessions`              | GET    | всички записи                                             |
| `/api/sessions/{id}`         | GET    | отчет за запис                                            |
| `/api/sessions/{id}`         | PATCH  | `{"name": "...", "note": "..."}` – име и/или бележка      |
| `/api/sessions/{id}`         | DELETE | изтриване                                                 |
| `/api/sessions/{id}/csv`     | GET    | измерванията като CSV                                     |

Съобщението `data` съдържа `db`, `dba`, `dbc` (Fast), `levels` (всички комбинации
A/C/Z × F/S), `peak_db`, `peak_freq`, `waveform[512]`, `spectrum[128]` и `octaves[31]`.
